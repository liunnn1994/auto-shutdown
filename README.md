# auto-shutdown —— 无线广播失联自动关机

开发板插在普通市电上，PC 由 UPS 供电。PC 通过 Wi-Fi 扫描发送随机挑战，
开发板将 HMAC 应答放入无线广播；电脑只扫描，不连接开发板网络，不需要
开启电脑热点。开发板不连接路由器，不需要 Wi-Fi 账号、管理员密码或校时。

只有首次认证成功后才开始失联判定。默认连续 60 秒未收到有效应答时弹出 60 秒
关机倒计时；设备恢复认证后自动关闭倒计时。无线干扰、开发板崩溃或本机
网卡故障也可能触发失联，这是保守的关机策略，不能独立证明市电断电。

成功认证并进入监控后，首次认证失败时界面显示黄色“未收到应答，正在确认”；
从最后一次成功认证起满配置的失联秒数（默认 60 秒），在下一轮失败检查时判定失联并启动倒计时。
阈值前恢复认证会恢复绿色在线状态。尚未成功认证过的监控目标只会等待，不会
因为启动后一直找不到设备而触发关机。

## 使用

1. 按下方“构建密钥”配置 `.env.local`，再烧录 [ESP8266 固件](ESP8266/README.md)，
   把开发板插在普通市电上。
2. 编译并启动 PC 程序：`mise exec -- cargo build --release --locked`，产物为
   `target/release/auto-shutdown.exe`。退出旧程序后启动新版。
3. 程序自动扫描并认证开发板，未发现时继续重试。可在“设备配置”中重新
   扫描，或输入 `radio://六位芯片ID`（例如 `radio://d86071`），点击“测试”检查
   认证，再点击“启动监控”。测试本身不会切换目标或启动监控。
4. 开机启动可在主界面或托盘菜单开启，通过任务计划程序在用户登录时
   静默启动；关闭/最小化窗口会隐藏到托盘，右键托盘“退出程序”才会退出。

Windows 需要无线网卡启用、WLAN AutoConfig 服务运行，并允许定位访问以
进行 Wi-Fi 扫描。电脑可以继续连接原 Wi-Fi；扫描期间可能短暂增加网络延迟。
每轮认证结束后等待 15 秒再扫描；每个无线接口最多扫描两次，每次等待扫描
完成最多 5 秒。因此不是严格每 15 秒一次，弹窗也不保证恰好在配置的阈值秒数出现。

发现多个认证设备时自动选择芯片 ID 数值最小的一台，并非信号最强的一台。
如需监控指定开发板，请手动输入其标识。手动切换目标会重新等待首次成功认证。

倒计时支持立即关机、取消本次关机、稍后 30 秒再提醒。取消后需认证恢复，
下次失联才会重新提醒。“稍后”会在 30 秒后重新弹出完整倒计时（默认 60 秒）；
期间恢复认证会取消重弹。倒计时归零会真实执行 `shutdown /s /t 0`。

PC 每次启动重新发现设备，不保存设备标识。程序只接受广播设备标识，
已移除 IP 心跳、UDP 发现、Python 模拟服务端和网页配网管理功能。

## 关机策略配置

主界面默认收起的“配置”包含“设备配置”和“关机策略”。设备配置提供扫描、测试和
“启动监控”，地址只在内存中生效；底部统一的“保存”按钮仅保存关机策略。
“关机策略”可修改“失联超时（秒）”和“关机倒计时（秒）”，默认均为 60 秒。
只接受大于 0 的十进制整数，最大 4294967295 秒。输入框允许暂时清空以便编辑，
空值不能保存。点击“保存”后才写盘并生效；写入失败时保留原配置。
失联时长调整不会重置最后一次成功认证时间，在下一轮认证失败检查时按新阈值判定。
倒计时弹窗打开期间不可修改策略。

配置文件位于用户目录 `~/.auto-shutdown/config.ini`，使用标准库读写简单的 `key=value`
文本，不新增第三方依赖。例如：

```ini
heartbeat_timeout_seconds=60
countdown_seconds=60
```

文件不存在、无法读取或内容无效时使用默认值；启动时不会生成或修复配置文件。
只有在界面修改配置并保存后才生成文件。重新启动程序后读取已保存的配置。

## 构建密钥

PC 与固件从仓库根目录的 `.env.local` 读取同一个 `AUTO_SHUTDOWN_RADIO_KEY`，
值为密码学安全随机生成的 32 字节密钥，以 64 位十六进制填写，不带引号。
格式见 [.env.example](.env.example)。首次配置可在 PowerShell 7 中执行：

```powershell
if (Test-Path .env.local) { throw '.env.local 已存在，请勿覆盖正在使用的密钥' }
$radioKey = [Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32)).ToLowerInvariant()
Set-Content -LiteralPath .env.local -Value ('AUTO_SHUTDOWN_RADIO_KEY=' + $radioKey) -Encoding utf8
Remove-Variable radioKey
```

本地文件已加入 `.gitignore`；示例不含可用密钥。缺失、空值、格式错误、重复配置
或全零密钥都会阻止构建，不回退到旧默认口令。`cargo build` 自动读取配置，
修改后会重新构建；固件使用 `./scripts/build-firmware.ps1` 读取同一文件再编译。
使用 Arduino IDE 时先执行 `./scripts/build-firmware.ps1 -PrepareOnly`，生成被
Git 忽略的 `ESP8266/radio_key.local.h`，然后打开 `ESP8266/ESP8266.ino` 上传。
更换密钥后必须重新构建 PC 并烧录固件，两端旧密钥与新密钥无法互相认证。

密钥编入 exe 与固件，运行时不需要 `.env.local`。Git 忽略只能防止源码意外提交，
不能防止持有程序或固件的人提取密钥；构建产物和本地配置均应按含密钥文件保管。
每套独立部署应使用不同密钥，所有共享同一密钥的设备属于同一认证范围。

## 自启动与升级

程序使用 Windows 原生 WLAN、托盘和任务计划程序接口，当前面向 Windows。
开机启动实际为**当前用户登录时启动**，不是系统服务；未登录时不运行监控。
任务位于任务计划程序根目录，名称为 `auto-shutdown`，以普通用户权限运行，
允许电池供电且不限制运行时长。任务启动参数为 `--from-autostart`，窗口直接
隐藏到托盘；手动启动会显示主窗口。

自启动已开启时，最后一次正常启动的 exe 会接管任务路径（debug、release 或
移动后的副本均如此）。升级时先从托盘退出旧版，再从固定位置启动新版并检查
开机启动开关。重复启动会唤出已有实例；即使新副本因此退出，它仍会先同步
自启动任务路径。关闭开关会删除任务。

从旧版迁移时请同时更新 PC 与固件。旧 IP 地址、网页配网和 ASR1 设备均不可
用于当前监控；设备标识仅在本次运行生效，重启会重新扫描选择。

## 诊断与日志

运行 `auto-shutdown.exe --radio-check` 只做无线扫描与认证，不启动 UI、监控
或关机。结果写入 `~/.auto-shutdown/logs/app-日期.log`，包含扫描错误、BSS
数量、新接收广播数量和认证设备数量。正常监控的认证状态也记录在此文件。

PowerShell 示例（release 版通常没有控制台输出）：

```powershell
$diagnostic = Start-Process -FilePath .\target\release\auto-shutdown.exe -ArgumentList '--radio-check' -Wait -PassThru
$diagnostic.ExitCode
Get-Content (Join-Path $env:USERPROFILE ('.auto-shutdown/logs/app-' + (Get-Date -Format yyyy-MM-dd) + '.log')) -Tail 40
```

退出码 `1` 表示扫描诊断返回错误；`0` 也可能表示扫描成功但认证设备数为 `0`。
必须检查日志中的认证设备数及标识。诊断只写主程序扫描结果，不写 `esp` 遥测；
后者由正常监控或手动“测试”的成功认证写入。

`esp-日期.log` 记录认证应答中的芯片 ID、运行秒数、启动随机标识、应答序号、
信号强度、可用/最低堆内存、最大空闲块、碎片率、复位原因、异常指令地址、
异常访问地址及接收/拒绝请求计数。时间戳使用 PC 本地时间。日志按天分割，
启动和跨天写入时删除修改时间早于 30 天的 `.log` 文件。

固件没有持久化日志；串口（115200）输出启动与周期统计。异常地址的定位
需要保留与烧录固件匹配的 `.elf`。正常复位应答中的异常字段为零。

| 现象 | 检查方法 |
|---|---|
| 错误码 `5` | 检查 Windows 定位访问权限 |
| 错误码 `1062` | 检查 WLAN AutoConfig 服务是否运行 |
| 错误码 `5023`、无线网卡列表为空 | 启用无线网卡，关闭飞行模式；仅有有线网络不能完成广播认证 |
| 能看到热点，但认证设备数为 `0` | 核对两端版本、构建密钥、开发板供电及串口；热点可见只说明收到了普通广播 |
| 一直等待首次有效心跳 | 尚未对当前监控目标认证成功；确认芯片 ID，检查手动测试结果 |
| 已在线后变黄、最终失联 | 查看最后成功认证时间与扫描错误；无线干扰、驱动异常也会触发策略 |
| 自启动运行了旧副本 | 退出旧程序，从预期路径启动新版，再检查任务动作路径 |

## 广播协议 ASR2

PC 使用 `WlanScan` 的自定义 IE 发送挑战；固件收到并认证后更新 Beacon 和
Probe Response。PC 等待扫描完成，通过 `WlanGetNetworkBssList` 读取原始 IE。
若第一次未收到应答，用同一挑战再扫一次；每轮重新生成 128 位随机数。
接收时间早于本轮挑战、错误随机数、错误设备 ID 或错误 HMAC 的应答都不会
刷新在线时间。协议不需要双方时钟同步。

ESP8266 NONOS SDK 的 IE 封装为：
`DD | 长度 | 18 FE 34 | DD 01 | 02 53 44 | 载荷`。
其中 `18 FE 34` 为 SDK 外层 OUI，`02 53 44` 为本协议私有厂商标记。

HMAC 直接使用 `.env.local` 中的 32 字节密钥，标签为 HMAC-SHA256 前 16 字节，
覆盖标签字段之前的整个载荷。芯片 ID 不构成独立密钥。字段布局仍为 ASR2，
但不再使用旧的固定口令派生密钥，因此必须同时更新两端。

固件使用固定 8 槽 FIFO，不覆盖待处理请求；令牌桶允许突发 8 次请求，此后
每 16 ms 补充一次验证额度。格式错误、队列内重复请求及近期已拒绝的相同报文
提前丢弃；每轮主循环最多验证一次 HMAC，并让出执行时间给 SDK。成功应答
最短发布间隔为 250 ms，记录最近 64 个成功发布的随机数，10 分钟内拒绝重放。
限流和去重丢弃数记录在串口 `dropped` 中，不为每个垃圾包写日志。

这些措施限制应用层 CPU、内存和应答更新开销，不能保证攻击期间认证仍可用。
连续不同的垃圾请求仍可能挤占接收额度，射频干扰也无法由 HMAC 或限流消除；
若最终持续无法认证，仍按配置的失联策略（默认 60 秒）处理。

所有多字节整数为大端：

| 载荷 | 布局 |
|---|---|
| 挑战，37 字节 | `ASR2` + 类型 `01` + 随机数 16 字节 + 标签 16 字节 |
| 应答，91 字节 | `ASR2` + 类型 `02` + 随机数 16 字节 + ID u32 + uptime u32 + boot u64 + 序号 u32 + 堆内存 u32 + 最低堆内存 u32 + 最大空闲块 u32 + 碎片率 u8 + 复位原因 u8 + 异常原因 u32 + 异常指令地址 u32 + 异常访问地址 u32 + 接收计数 u32 + 非法计数 u32 + 标签 16 字节 |

ASR2 与之前的 ASR1 不兼容，两端必须一起更新。广播 AP 使用每次启动随机
生成的密码防止客户端加入，不提供 DHCP、Web 或 IP 心跳服务。电脑扫描广播
无需知道这个临时密码。

## 开发与验证

PC 构建需要 Windows Rust MSVC 工具链和 Visual Studio C++ 构建工具（含
Windows SDK）。仓库的 `.mise.toml` 固定 Rust 版本；先执行 `mise install`。
当前程序与固件不需要安装 Node/pnpm 或 Python 心跳服务依赖。

```powershell
mise exec -- cargo test --locked
mise exec -- cargo clippy --all-targets --locked
```

Rust 测试使用 `tests/radio-vectors.json` 中的协议向量，覆盖篡改、重放、截断、
IE 边界，以及首次认证前不关机、可配置的失联阈值、失联只上报一次和恢复后重新戒备。
另有构建密钥配置校验测试；公开测试向量使用独立测试密钥，不依赖本地部署密钥。

固件构建及实机验收见
[ESP8266 说明](ESP8266/README.md)。

自动化测试验证协议编解码和监控状态转换，不覆盖网卡驱动的空中收发、真实
开发板、弹窗交互或实际关机。完成编译、看到热点或取得 BSS 列表，均不能单独
证明完整无线认证和断电恢复链路已通过；实机验收需要保留对应日志。

代码入口：`src/radio.rs` 为 Windows 扫描，`src/radio_protocol.rs` 为认证解码，
`src/monitor.rs` 为失联监控，`ESP8266/ESP8266.ino` 为固件，
`ESP8266/radio_protocol.h` 为固件协议编码。
